# trade-calc

A profit calculator for crafted items in **Albion Online**. The full functional spec
(what the UI will do for which city/category/quality) lives in `trade-calc-spec.md` —
that file is the single source of truth for behavior; this README documents what is
**implemented** today and the verified game facts behind it.

## Current state

Implemented so far:

- **Recipe book** — 7103 recipes (1656 base + 5447 enchantment variants, T2–T8,
  all five refining chains) in German, loaded at startup from
  `src/main/resources/data/recipes.json`. Lookup via `RecipeService`
  (`findByItemId`, indexed; `@Cacheable("recipes")`). Runs on
  **Spring Boot 4.1.1** (Jackson 3, `@MockitoBean` in tests, cache/webmvc
  starters as explicit modules).
- **Market price service** — `PriceService` turns the hourly sell history from the
  [Albion Online Data project](https://www.albion-online-data.com/api/) (Europa
  server) into the spec's list-view numbers, in one batched API call per list page:
  - `unitsPerDay` = Σ item_count ÷ 28, summed over all qualities
  - `priceByQuality` = volume-weighted average price per quality level 1–4
    (Σ item_count × avg_price ÷ Σ item_count; a quality with zero sales has no entry)
  - `BigDecimal` money math (price scale 2, units scale 1, commercial rounding
    `HALF_UP`);
    `@Cacheable("prices")` on the (item ids, city) pair.
  - The API throttles aggressively (HTTP 429 "be nice…"), so the list view
    fetches market data **only once the user restricts the selection** to a
    concrete category or subcategory; unrestricted ("Alle") pages sort
    alphabetically without any API call.

Not yet implemented (see spec): the "Berechnen" Variante 2 (refining-chain math).

## Build, test, run

```bash
mvn verify              # Unit tests + integration test + JaCoCo coverage gate
mvn test                # Unit tests only
mvn spring-boot:run     # App on http://localhost:8080
mvn -Dtest=PriceServiceTest test    # Run a single test class
```

Coverage report after `mvn verify`: `target/site/jacoco/index.html`.

Tests never hit the real Albion API — the HTTP layer is stubbed
(`MockRestServiceServer` for the HTTP client, a stub `MarketPriceHistoryClient`
for the service math).

## Recipe data pipeline

`src/main/resources/data/recipes.json` (~7100 recipes, compact JSON, 2.6 MB) is
generated by `scripts/build_recipes.py` from the
[ao-data/ao-bin-dumps](https://github.com/ao-data/ao-bin-dumps); the script needs
`data/raw/items.json` + `data/raw/localization.json` (cached in `data/raw/`,
not in git). Item names come from the dumps' **official German localization**
(DE-DE first, EN fallback); the shop category/subcategory display labels
(`shopSub1`/`shopSub2`) are hand-curated in the script — the dump carries no
localization for those.

Re-run with cwd = repo root whenever the recipe data changes:

```bash
python3 -I scripts/build_recipes.py
```

Refining facts encoded in the data (verified against the dump): the raw-material
input per refined unit grows with tier — Planks/Cloth/Leather/Bars/Blocks take
1, 2, 2, 3, 4, 5, 5 raw units for T2…T8 plus one refined piece of the previous
tier. The API only accepts exact dump ids (e.g. `T4_2H_BOW`, not `T4_BOW`) —
`recipes.json` uses those same ids 1:1.

## Configuration

All external settings flow through `config/PriceProperties`
(`@ConfigurationProperties(prefix = "price")`, see `application.yml`):

| Key | Default | Meaning |
|---|---|---|
| `price.base-url` | `https://europe.albion-online-data.com` | market data host (Europa) |
| `price.history-path` | `/api/v2/stats/history` | history endpoint |
| `price.history-days` | `28` | averaging window (spec: last 4 weeks) |
| `price.qualities` | `1,2,3,4` | quality levels fetched in one request |
| `price.connect-timeout-ms` / `price.read-timeout-ms` | 2000 / 5000 | HTTP timeouts |

Cache names are declared in `application.yml` (`recipes`, `prices`) — a new
`@Cacheable` name must be added there or it silently no-ops.

## Game data: refining & crafting bonuses

`src/main/resources/data/bonuses.json` stores **production bonuses** (not return
rates) per Royal City, e.g. a specialized city's refining bonus is `0.40`
(Lymhurst/Fiber, Fort Sterling/Wood, Martlock/Hide, Bridgewatch/Stone,
Thetford/Ore; base 0.18 everywhere, no refining specialization in Caerleon,
Brecilien or the Black Market).

The in-game **resource return rate (RRR)** players see — e.g. the well-known
36.7 % when refining Fiber in Lymhurst — is derived from the production bonus:
`RRR = 1 − 1/(1 + bonus)`. So 58 % total bonus (= 0.18 + 0.40) → 36.7 % return.
The calculation code must apply this formula; do not mix the two numbers up.

Verified value table (refining, Europa royal continent):

| Location | Production bonus | RRR without focus | RRR with focus |
|---|---|---|---|
| Royal City, wrong resource (base)        | 18 %          | 15.3 % | 43.5 % |
| Royal City, its specialty resource       | 18 % + 40 %   | 36.7 % | 53.9 % |
| Caerleon                                 | 18 % only     | 15.3 % | 43.5 % |
| Brecilien / Black Market                 | — (no refining specialization) | — | — |

Crafting focus adds a flat +59 % production bonus while it lasts; city daily
bonuses can add a further +10 %/+20 % (→ e.g. 49.2 % RRR in the specialty city).
For refining-chain math (spec "Variante 2") the without-focus numbers apply:
refine in the specialty city (36.7 % return) and the RRR formula turns a chain
like `32 T4 Planks + 96 T5 Wood` into its effective output.
