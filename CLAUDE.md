# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

A Spring Boot 4.1.1 (Java 21, Maven) profit calculator for crafted items in Albion Online. The spec is `trade-calc-spec.md` (in German).

**Note:** The codebase is at Phase 6 of the roadmap; only `domain/` (`Recipe`, `RecipeIngredient`), `dataprovider/recipe/RecipeLoader`, and `service/RecipeService` exist. Check `src/main/java` before assuming a class is real.

## Commands

```bash
mvn verify              # Unit + integration tests + JaCoCo coverage gate
mvn test                # Unit tests only
mvn spring-boot:run     # App on http://localhost:8080
mvn -Dtest=RecipeServiceTest test           # Single test class
mvn -Dtest=RecipeTest#someMethod test       # Single test method
```

- Coverage gates fail `verify`: ≥ 80% branch, ≥ 70% line on the BUNDLE. Report at `target/site/jacoco/index.html`.
- Test split by suffix, not annotation: `*Test.java` = Surefire unit tests, `*IT.java` = Failsafe integration tests (`@SpringBootTest`). Never name an integration test `FooTest`.
- No separate linter step.

## Architecture

Hexagonal-lite layering rooted at `de.am.tcalc`:

- **`domain/`** — pure records/enums, **no Spring imports**. Construct directly in tests (no DI).
- **`dataprovider/recipe/`** — `RecipeLoader` reads `classpath:data/recipes.json` **once at construction into a `final` field**. No `@Cacheable` on the loader, no exists()/double-IO patterns.
- **`service/`** — `RecipeService` wraps the loader with a precomputed index; `findByItemId` is `@Cacheable("recipes")`. Cache names are declared in `application.yml` (`spring.cache.cache-names`) — a new `@Cacheable` name must be added there or it silently no-ops.

Data flow (so far): `RecipeLoader` → `RecipeService` (indexed look-up). Later phases add `PriceService` (albion-online-data.com API), `ProfitCalculationService` + strategy classes, REST controller, Thymeleaf/HTMX UI — see README phases for the planned design; slot new work into those phases rather than inventing a parallel structure.

## Recipe data pipeline

`src/main/resources/data/recipes.json` (~4200 recipes) is generated by `scripts/build_recipes.py` from [`ao-data/ao-bin-dumps`](https://github.com/ao-data/ao-bin-dumps); the script downloads `items.json` to `data/raw/`. CI (`.github/workflows/build.yml`) caches `data/raw`, runs the script, then `mvn verify`. `scripts/` also has inspection/verification helpers (`verify_recipes.py`, `count_recipes.py`, …). Re-run `python3 scripts/build_recipes.py` (cwd must be repo root — it writes into `src/main/resources`) if the recipe data changes.

## Conventions

- Apache 2.0 header (`Copyright 2026 Martin Absmeier.`) on every Java file.
- Lombok on service classes (`@Slf4j` etc.); records use canonical constructors, no `@Builder`. Match the closest sibling file.
- Configuration goes through `*Properties` classes (`@ConfigurationProperties`), never hard-coded.
- Monetary math: `BigDecimal` + `RoundingMode.HALF_UP` when money appears (money scales 2, ratios 4). Never `double` for prices/bonuses.
- Tests never hit the real Albion API — stub the HTTP layer.
- Follow `AGENTS.md` ("ponytail" minimal-diff discipline). Mark deliberate simplifications with a `ponytail:` comment naming the ceiling and upgrade path.
- Bonus/category strings in JSON data may be German with umlauts (`Holz`, `Bögen`) — keep them intact.
